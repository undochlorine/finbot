# 4.3.2 Hosting provision and go-live

- **Status:** `todo`
- **Goal:** production bot is live on Railway with managed Postgres + Redis, backups proven, operator can inspect data from a browser and a local client.

Depends on `4.3.1` in git. Most clicks are the operator; the agent stays on the checklist, README, and any secret-name mismatches.

## In scope

Operator (agent may pair, not silently click paid UIs):

1. Railway account, **Hobby** (or whatever current equivalent), **spend alert**, project in **EU**.
2. Add **Postgres** and **Redis**. Turn on / confirm Postgres automated backups.
3. Add the **bot worker** from this repo’s Dockerfile. **Replica count 1.** App sleep / scale-to-zero **off**. No public domain.
4. Variables on the worker: `BOT_TOKEN`, `DATABASE_URL` (private), `REDIS_URL` (private), `ADMIN_TELEGRAM_ID`, `LOG_LEVEL=info`. Keep `TRIAL_DURATION` / `DEFAULT_CURRENCY` defaults unless already set locally.
5. GitHub Actions secrets so the `4.3.1` deploy job actually runs (`RAILWAY_TOKEN` and ids from `4.3.1` README).
6. First production deploy via merge to `master` / `main` (or a no-op commit after secrets exist). Confirm the Actions deploy job ran, not a Railway-side git deploy.
7. Smoke: Telegram `/start`. Restart worker; `/banks` still there. Optional: in-flight wizard + Redis restart → wizard gone.
8. **Restore drill:** note a row (or create a throwaway bank), restore a backup (scratch database or Railway restore), prove the data is there. Record the exact steps in README.
9. Access proof (both paths):
   - Browser: Railway Postgres UI and Redis UI (or vendor console).
   - Local: TablePlus or `psql`, and Redis Insight or `redis-cli`, via Railway’s public/TCP proxy with TLS/password. App remains on private URLs.
10. Confirm logs visible in Railway for a `/start`. Glance at CPU/memory graphs (no extra stack).

Agent:

- Fill README with the real (non-secret) runbook: region, service names, how to open the proxy, restore clicks, log UI.
- Unskip the deploy job if `4.3.1` used “skip when secrets missing.”
- Do **not** commit tokens, public `DATABASE_URL` passwords, or `.env`.

## Out of scope

- Replicas, webhooks, partitioning, PgBouncer (`4.9`)
- Product dashboards (`4.17`)
- Landing (`4.18`)
- Re-implementing adapters
- Switching to Hetzner/Fly unless the operator rejects Railway’s bill (then update the design first)

## DoD

- Telegram talks to the **hosted** process (not a laptop `go run`)
- Postgres holds banks across a worker restart
- One restore drill has been done and written down
- Operator opened Postgres and Redis from a browser **and** a local client
- Merge to `master` / `main` deploys only after `common`
- Replica count is 1; a second replica is not running
- Design: [`docs/superpowers/specs/2026-09-09-hosting-design.md`](../../superpowers/specs/2026-09-09-hosting-design.md)
