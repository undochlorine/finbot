# 4.1.1 Postgres foundation

- **Status:** `done`
- **Goal:** a production-shaped Postgres **process** locally and in CI, plus `Open` that pools, times out, pings, and applies a baseline schema. `cmd/bot` still uses SQLite.

**Design (read with this file):** [`docs/superpowers/specs/2026-09-09-postgresql-migration-design.md`](../../superpowers/specs/2026-09-09-postgresql-migration-design.md)

## In scope

- `docker-compose.yml`: `postgres:16`, healthcheck `pg_isready`, named volume, user/password `finbot`/`finbot` (local/CI only). Init creates databases `finbot` (bot) and `finbot_test` (integration).
- GitHub Actions `integration-test` job: Postgres **service container** (same image/user/password, `POSTGRES_DB=finbot_test`). Wait on healthy. `POSTGRES_TEST_URL` for tests. Do not require Compose in CI.
- `internal/adapter/postgres`: `Open(ctx, url)`, `pgx` stdlib driver, ping, embed migrator, `001_init.sql` baseline (do **not** replay SQLite `001`–`003`).
- Pool constants: `MaxOpenConns = 10`, `MaxIdleConns = 5`, `ConnMaxLifetime = 30m`, `ConnMaxIdleTime = 5m`.
- After connect: `statement_timeout = 5s`, `lock_timeout = 2s`, `idle_in_transaction_session_timeout = 10s`.
- `schema_migrations` + transactional apply; second `Open` is a no-op for already-applied versions.
- `make test-integration` also runs `./internal/adapter/postgres/...` (`//go:build integration`). SQLite tests stay until `4.1.3`.
- Optional: parse `DATABASE_URL` / `POSTGRES_TEST_URL` in config **without** switching `cmd/bot`.

## Out of scope

- Repository methods, `Transactor`, `FOR UPDATE`, wiring `cmd/bot` to Postgres
- Deleting SQLite
- Managed hosting, TLS, backups (`4.3`)
- Partitioning (`4.9`)

## Schema (must match the spec)

- `BIGINT` for `telegram_id`, bank/operation ids (`GENERATED BY DEFAULT AS IDENTITY`)
- `TIMESTAMPTZ` timestamps; `BOOLEAN` `include_in_total`
- Same CHECKs/FKs as today’s product: cascade user delete; `operations.bank_id` `ON DELETE SET NULL`; operation types include `rename`
- `name_normalized` unique per `(user_id, name_normalized)`
- Indexes: `banks (user_id)`; `operations (user_id, created_at DESC)`; `operations (bank_id)`; `users (last_activity_at)`

## DoD

- `docker compose up -d` yields a healthy Postgres; tests can connect to `finbot_test`
- CI integration job uses the service container and passes without a local Compose daemon
- Opening twice applies `001_init` once
- Ping/migrate failure returns an error (no silent empty schema)
- `make lint` after Go changes
- Unit tests still do not need Postgres

## Tests

- Idempotent migrate (open → close → open; one `001_init` row)
- Expected tables/indexes exist (query `pg_indexes` / `information_schema`)
- Integration tests **fail** (not skip) if Postgres is unreachable; error text tells the operator to start Compose. CI always has the service container.
