# 4.1.2 Postgres adapter

- **Status:** `done`
- **Goal:** Postgres implements the same service ports as SQLite, with row locks and lock-order so money writes are safe under a connection pool. `cmd/bot` still opens SQLite.

**Depends on:** `4.1.1` `done`. **Design:** [`docs/superpowers/specs/2026-09-09-postgresql-migration-design.md`](../../superpowers/specs/2026-09-09-postgresql-migration-design.md)

## In scope

- `UserRepository`, `BankRepository`, `OperationRepository`, `Transactor` in `internal/adapter/postgres`
- `$1` placeholders, `RETURNING` (no `LastInsertId`)
- `TIMESTAMPTZ` / `BOOLEAN` scan in conv helpers
- Unique violation `23505` → `domain.ErrBankNameTaken`
- `GetByID` / `GetByName`: `FOR UPDATE` **only** when `InTx` stored a `*sql.Tx` on the context; unlocked otherwise
- `InTx`: begin/commit/rollback; retry up to **3** times on `40P01` and `40001` only
- `Transfer` lock order: load banks by **ascending id**, then apply from/to (`internal/service` change is allowed; keep ports)
- Integration tests against `finbot_test` covering isolation, unique names, and write-path atomicity (add/spend/set/delete/rename/transfer), equivalent to today’s sqlite cases
- Prefer tests through `service.New` + postgres repos (or a tiny `storetest` on those interfaces). Mockery stays for unit tests. Do not hand-write repository fakes.

## Out of scope

- Switching `cmd/bot` to Postgres (`4.1.3`)
- Deleting `internal/adapter/sqlite`
- Partitioning, PgBouncer, advisory locks
- Changing command UX

## DoD

- Postgres repos compile-time satisfy the service interfaces (`var _ service.X = (*Y)(nil)`)
- Concurrent unique insert maps to `ErrBankNameTaken`
- Add/spend/set/delete/rename/transfer keep bank + operations row in one tx (rollback on error)
- Display reads (`List`, `Total`, `Get` outside tx) do not take `FOR UPDATE`
- `make test-integration` and `make lint` pass

## Tests

Reuse the sqlite behavioral intent:

- Per-user isolation (list/get/update/delete cannot see another user’s banks)
- Unique `name_normalized` / recase rules via domain + unique constraint
- Reopen (new `Open`) still sees rows
- Write-path: operation appended iff the bank mutation commits
