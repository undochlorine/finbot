# 4.14.3 FX transfer

- **Status:** `todo`
- **Goal:** a `/transfer` between two currencies shows the converted amount and the rate, then moves money only after Yes. The two currencies may sit in different banks or in the same bank.
- **Depends on:** [`4.14.1`](4.14.1-fx-rates.md) and [`4.14.2`](4.14.2-currency-balances.md).
- **Read with this file:** [`requirements.md`](../requirements.md) (Currencies and FX), [`areas/telegram.md`](../areas/telegram.md), [`areas/service.md`](../areas/service.md), [`areas/persistence.md`](../areas/persistence.md).

The amount is a number in the **source** currency (`10`, `10.5`, `10.50`). The currency itself was chosen in [`4.14.2`](4.14.2-currency-balances.md) or in the destination step below.

## Same currency

Two different banks, one code. Keep the `4.14.2` path: no `Quote`, no extra confirm, one operation, `meta` = destination bank id, both balances move by the same cents. Create the destination row when it is missing. `dest_currency`, `dest_amount_cents`, and `fx_rate` stay NULL.

The same bank and the same currency is `ErrSameBank`. No write.

## Different currency

This includes another bank and the same bank. After a valid amount, do not write yet.

1. `Quote(sourceCurrency, destCurrency)`.
2. Convert in domain, not with `float64`:

   `dest = round_half_away_from_zero(sourceCents × DestPerSource)` to an integer number of minor units.

   Half away from zero: `1.5` → `2`, `-1.5` → `-2`. Transfer amounts are positive; lock the negative rule anyway.
3. `dest == 0` → `ErrConvertedAmountZero`. Stay on the amount step:

   `That amount is too small to convert. Send a larger amount.`

4. Overflow `int64` → the usual invalid amount.
5. `ErrRateUnavailable` (no cache and feed down, or this pair is missing) ends the flow without moving money:

   `I could not get an exchange rate. Nothing was moved.`

6. Otherwise edit the wizard prompt. English source, catalogs `en` / `ru` / `uk` / `md`. Both amounts use `FormatMoney`. The rate is units of destination for **1** source unit, up to 8 decimal places, trailing zeros removed (`1:30`, `1:45.286607`, `1:0.022039`). The destination amount is what will be credited; the rate text is the explanation.

   Two banks:

```text
A transfer of $10.00 from "A" to "B" will be 300.00 UAH, based on an exchange rate of 1:30. Confirm?
```

   Same bank:

```text
Converting $10.00 in "Travelling" will add 40.00 PLN, based on an exchange rate of 1:4. Confirm?
```

7. Yes / No use the localized Yes/No labels. Callbacks `v1:transfer:fx:ok` and `v1:transfer:fx:no` carry no amounts. The FSM holds `from_id`, `to_id`, both currency codes, source cents, and dest cents. `from_id == to_id` is valid when the codes differ.
8. No → `Okay, I didn't transfer anything.` `/cancel` → `Canceled.` No write.
9. Yes runs `Transactor`. Two banks: lock by ascending id. One bank: lock that row. Reload inside the transaction.
   - The source bank, the destination bank, or the source currency row is gone → write nothing and say the banks changed. The user starts `/transfer` again. A missing destination currency is fine: this step creates it.
   - Recompute the quote. If the new dest cents differ from the FSM, write nothing and replace the prompt with the new confirm.
   - Otherwise debit the source by the source cents and credit the destination by the dest cents, inserting the destination row when needed. A negative source balance stays allowed.
10. One `transfer` operation on the source bank. `currency` is the source code. `amount_cents` is the positive source amount. `balance_after_cents` is the source balance after. `meta` is the destination bank id, which may equal the source id.
11. Migration `005_transfer_fx.sql`:
    - `dest_currency TEXT NULL`
    - `dest_amount_cents BIGINT NULL` — cents credited to the destination currency
    - `fx_rate TEXT NULL` — decimal string of destination units per 1 source unit, the quote ratio, not the rounded label and not `float64`

    All three NULL when the currencies match. All three set when they differ. Add a check that the three are all NULL or all set.
12. Success edits the prompt into an outcome (💸, buttons removed). Name both amounts and both new balances of those currencies with `FormatMoney`. On one bank, both balances belong to that bank. A second tap is a stale callback and must not move money again.
13. Widen `Transfer` to take a source currency and a destination currency. Same codes keep the `4.14.2` write and must not call `Quote`. Different codes use the confirm path. `ErrSameBank` remains the rejection for one bank and one code.
14. Wire `internal/adapter/fx` into `cmd/bot` with the production Redis cache and `net/http`. Service takes `RateProvider`.

## Wizard

From-bank → source currency → to-bank → destination currency → amount.

- Source currency: balances on that bank only. One balance skips the step. Zero banks still point at `/newbank`.
- To-bank includes the source bank.
- One bank with one currency: do not open the wizard. Tell the user they can add a currency with `/add` or create a bank with `/newbank`.
- One bank with two or more currencies: that bank is the source and the destination. Skip both bank steps.
- Destination currency on another bank: buttons for balances already there, plus the source currency when it is missing, plus the usual picker row with codes already shown removed. A typed code goes through `ParseCurrency`.
- Destination currency on the same bank: hide the source currency. Typing it stays on the step (`Choose a different currency.`). The picker row remains for a new code.
- Skip the destination step only in two cases. The other bank has exactly one balance and it equals the source currency: ask for the amount, then write with no confirm. The same bank has exactly one other currency: use that currency, ask for the amount, then confirm.

`4.14.2` wrote a 3-token shortcut as a same-currency move whenever the source had one balance. Replace that. See the shortcut rules below.

## Shortcuts

Single-word bank names. A longer name uses the wizard. Currency tokens go through `ParseCurrency`. An amount is `ParseMoney`.

1. Five tokens, `Bank Currency Bank Currency Amount`, both banks exist → that pair of currencies.
2. Four tokens, `Bank Currency Currency Amount`, the bank exists, and token 3 is a currency and not an existing bank name → same bank, those two currencies. The same code is `ErrSameBank`.
3. Three tokens, `Bank Bank Amount`, both banks exist, and each has exactly one balance → those two currencies. Equal codes write immediately. Different codes stop at the confirm. Do not open the source currency on the destination instead of converting.
4. Three tokens where a bank has several balances → do not guess a currency. Keep the banks and the amount, and ask for the missing currency.
5. Otherwise the full remainder is the from-bank name.

`/transfer A USD B 50` is four tokens whose third token is a bank, so it is not rule 2. It falls through to rule 5. Same-bank convert is `/transfer A USD PLN 50`. Two banks with both currencies named is `/transfer A USD B PLN 50`.

## Out of scope

- Converting `/all` or `/total`
- Deleting one currency
- A rate API key. The `FX_*` durations already exist from `4.14.1`; pass those parsed values into the adapter
- `/history` rendering of `dest_currency` and `fx_rate` (`4.10` can read the columns later)

## Tests

- Domain convert: `100` cents × `30/1` = `3000`; `1` cent × `3/2` = `2`; `1` cent × `1/1000` = `0` → `ErrConvertedAmountZero`; half-away `-3/2` → `-2`.
- Service, mockery `RateProvider`: different currencies call `Quote` once per attempt, including when both ids match; same currency does not; provider error leaves every balance; success stores `dest_currency`, `dest_amount_cents`, and `fx_rate`. Same bank and the same currency is `ErrSameBank`.
- Handler: the two-bank confirm and the same-bank confirm contain both formatted amounts. No writes nothing. Stale Yes does not double-post. One bank with one currency does not call `Quote`.
- Integration: a same-currency transfer row leaves the three new columns NULL; a cross-currency row written by the service (mockery `RateProvider`) stores all three. Same-bank FX stores `meta` as that bank id and a different `dest_currency`.
