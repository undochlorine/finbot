# 4.2.1 Redis foundation + Cache adapter

- **Status:** `done`
- **Goal:** a production-shaped Redis **process** locally and in CI, plus `Open` that pools, times out, pings, and implements `ports.Cache`. `cmd/bot` still uses `memorycache`.

**Design (read with this file):** [`docs/superpowers/specs/2026-09-09-redis-cache-design.md`](../../superpowers/specs/2026-09-09-redis-cache-design.md)

## In scope

- `docker-compose.yml`: `redis:7-alpine`, port `6379:6379`, `requirepass finbot`, `maxmemory 64mb`, `maxmemory-policy volatile-ttl`, healthcheck `redis-cli -a finbot ping`. No named volume.
- GitHub Actions `integration-test` job: Redis **service container** (same image/password, port 6379). Wait on healthy. `REDIS_TEST_URL` for tests. Do not require Compose in CI. Keep the existing Postgres service.
- `internal/adapter/rediscache`: `Open(ctx, url, prefix)`, `github.com/redis/go-redis/v9`, ping, `Close`. Empty prefix → `finbot:v1:`.
- Pool/timeout constants from the spec (Dial 3s, Read/Write 400ms, PoolTimeout 1s, PoolSize 10, MinIdleConns 2, idle 5m, lifetime 30m, MaxRetries 1).
- `Get` / `Set` / `Delete` on `ports.Cache`. Prefix every key. `redis.Nil` → miss. `ttl <= 0` on Set deletes. Canceled context returns error.
- `make test-integration` also runs `./internal/adapter/rediscache/...` (`//go:build integration`).
- Optional: parse `REDIS_URL` / `REDIS_TEST_URL` in config **without** switching `cmd/bot` (accept `redis://` and `rediss://`).

## Out of scope

- Wiring `cmd/bot` to Redis (`4.2.2`)
- Requiring `REDIS_URL` in `config.Load` for the bot
- Deleting `memorycache`
- Caching totals / banks
- Rate limit, locks, Cluster, FIFO-in-Redis
- Managed Redis (`4.3`)

## DoD

- `docker compose up -d` yields a healthy Redis; tests can connect with `REDIS_TEST_URL`
- CI integration job uses the Redis service container and passes without a local Compose daemon
- Ping failure returns an error (no silent empty client)
- Adapter compile-time satisfies `ports.Cache`
- Unique test prefixes; tests do not `FLUSHALL` / `FLUSHDB`
- `make lint` after Go changes
- Unit tests still do not need Redis

## Tests

- Behavioral KV cases matching `memorycache` intent: hit, miss, overwrite, delete, expire, `ttl<=0` deletes, canceled context, **key isolation** (Set `fsm:111` and `fsm:222` with different values; Get each; Delete one; the other remains)
- Integration tests **fail** (not skip) if Redis is unreachable; error text tells the operator to start Compose. CI always has the service container
