# 4.3 Cheap hosting that can scale

- **Status:** `todo`
- **Goal:** run the **stateless** bot plus a **managed PostgreSQL** with a low bill (Fly.io / Railway / Hetzner-class VPS — choose at the time). Dockerfile already exists.

## In scope (when this step starts)

- Choose host. App has no local disk requirement for the database (`DATABASE_URL` from `4.1.3`).
- Managed Postgres (or Postgres on the VPS with an ops story): disk size, TLS in the URL (`sslmode=require` or equivalent), secrets, automated backups and a restore drill (PITR if the vendor has it).
- Do **not** re-implement the adapter, pool, timeouts, or `FOR UPDATE` — those shipped in `4.1.x`. Point the existing URL at the hosted instance.
- Compose remains **dev/CI**. Production does not run the git `docker-compose.yml` database as the source of truth.
- A “product + bot link” page may ship here if a public URL is needed before prices exist. Landing with real plans is `4.18` and waits for `4.6`.

## Out of scope

- Partitioning, PgBouncer, app replicas, rate limits (`4.9`)
- Redis hosting if `4.2` already chose how Cache is deployed — wire it here only if not done
