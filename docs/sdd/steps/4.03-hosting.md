# 4.3 Cheap hosting that can scale

- **Status:** `todo`
- **Goal:** run the **stateless** bot plus **managed PostgreSQL and Redis** with a low bill (Fly.io / Railway / Hetzner-class VPS — choose at the time). Dockerfile already exists.

## In scope (when this step starts)

- Choose host. App has no local disk requirement for the database (`DATABASE_URL` from `4.1.3`) or for Cache (`REDIS_URL` from `4.2.2`).
- Managed Postgres (or Postgres on the VPS with an ops story): disk size, TLS in the URL (`sslmode=require` or equivalent), secrets, automated backups and a restore drill (PITR if the vendor has it).
- Managed Redis: point existing `REDIS_URL` at the vendor (`rediss://` already parsed in `4.2`). Do **not** re-implement the adapter, pool, or FSM TTL. Persistence of Redis is not a recovery requirement (FSM is expendable).
- Do **not** re-implement the Postgres adapter, pool, timeouts, or `FOR UPDATE` — those shipped in `4.1.x`. Point the existing URL at the hosted instance.
- Compose remains **dev/CI**. Production does not run the git `docker-compose.yml` Postgres or Redis as the source of truth.
- A “product + bot link” page may ship here if a public URL is needed before prices exist. Landing with real plans is `4.18` and waits for `4.6`.

## Out of scope

- Partitioning, PgBouncer, app replicas, rate limits (`4.9`)
