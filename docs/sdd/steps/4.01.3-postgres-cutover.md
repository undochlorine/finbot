# 4.1.3 Postgres cutover

- **Status:** `done`
- **Goal:** `cmd/bot` runs on Postgres only. SQLite is gone from the bot, Docker, CI, and human run docs.

**Depends on:** `4.1.2` `done`. **Design:** [`docs/superpowers/specs/2026-09-09-postgresql-migration-design.md`](../../superpowers/specs/2026-09-09-postgresql-migration-design.md)

## In scope

- `config.Load`: require `DATABASE_URL`; remove `SQLITE_PATH` from the bot
- `cmd/bot`: `postgres.Open`, postgres repos + `Transactor`; mkdir for sqlite path goes away
- `Dockerfile`: stop treating `/data/finbot.db` as the database (no SQLite volume as the store)
- `.env.example`, `README.md`, `docs/sdd/areas/persistence.md`, `docs/sdd/areas/platform.md`: Postgres + Compose as the local DB
- `make test-integration` / CI: postgres package only (drop sqlite integration job path)
- Delete `internal/adapter/sqlite` from the runtime (and its integration tests)
- Optional **best-effort** copy from a local `data/finbot.db` during this step (domain rows; preserve ids only if that is the simple `GENERATED BY DEFAULT` path). Missing file, empty DB, or partial failure: log and continue. **Not** a product feature, **not** a lossless gate. After cutover, leftover personal SQLite data may be dropped. Do not keep a second dialect in `cmd/bot`.

## Out of scope

- Managed Postgres, TLS, backups, restore drill (`4.3`)
- Partitioning, replicas, rate limits (`4.9`)
- Redis (`4.2`)

## DoD

- Bot does not start without a usable `DATABASE_URL`
- `go run ./cmd/bot` against Compose Postgres serves Telegram the same as the SQLite MVP (commands unchanged)
- CI has no sqlite adapter tests
- `modernc.org/sqlite` is not a runtime dependency of `cmd/bot`
- `make lint`, `make test-unit`, `make test-integration` pass
- Area docs describe Postgres as **current**, not upcoming

## Tests

- Config: missing/invalid `DATABASE_URL` fails load
- `cmd/bot` tests that assumed sqlite directory errors are updated
- Integration remains postgres-only
