# 4.14.2 FX transfer

- **Status:** `todo`
- **Goal:** a cross-currency `/transfer` shows the converted amount and the rate, then moves money only after Yes.
- **Depends on:** [`4.13.3`](4.13.3-currency-picker.md) and [`4.14.1`](4.14.1-fx-rates.md).
- **Read with this file:** [`requirements.md`](../requirements.md) (Currencies and FX), [`areas/telegram.md`](../areas/telegram.md), [`areas/service.md`](../areas/service.md), [`areas/persistence.md`](../areas/persistence.md).

The user never types a currency. The amount is in the **source** bank’s currency, parsed as today (`10`, `10.5`, `10.50`).

## Same currency

Keep today’s path: no `Quote`, no extra confirm, one operation, `meta` = destination bank id, both balances move by the same cents. `dest_amount_cents` and `fx_rate` stay NULL.

## Different currency

After a valid amount, do not write yet.

1. `Quote(from.Currency, to.Currency)`.
2. Convert in domain, not with `float64`:

   `dest = round_half_away_from_zero(sourceCents × DestPerSource)` to an integer number of minor units.

   Half away from zero: `1.5` → `2`, `-1.5` → `-2`. Transfer amounts are positive; lock the negative rule anyway.
3. `dest == 0` → `ErrConvertedAmountZero`. Stay on the amount step:

   `That amount is too small to convert. Send a larger amount.`

4. Overflow `int64` → the usual invalid amount.
5. `ErrRateUnavailable` (no cache and feed down, or this pair is missing) ends the flow without moving money:

   `I could not get an exchange rate. Nothing was moved.`

6. Otherwise edit the wizard prompt. English source, catalogs `en` / `ru` / `uk` / `md`:

```text
A transfer of $10.00 from "A" to "B" will be 300.00 UAH, based on an exchange rate of 1:30. Confirm?
```

   Both amounts use `FormatMoney`. The rate is units of destination for **1** source unit, up to 8 decimal places, trailing zeros removed (`1:30`, `1:45.286607`, `1:0.022039`). The destination amount is what will be credited; the rate text is the explanation.

7. Yes / No use the localized Yes/No labels. Callbacks `v1:transfer:fx:ok` and `v1:transfer:fx:no` carry no amounts. The FSM holds `from_id`, `to_id`, both currency codes, source cents, and dest cents.
8. No → `Okay, I didn't transfer anything.` `/cancel` → `Canceled.` No write.
9. Yes runs the existing `Transactor` path (lock the two banks by ascending id, then debit/credit). Reload both rows inside the transaction.
   - If either id or either currency differs from the FSM, write nothing and say the banks changed; the user starts `/transfer` again.
   - Recompute the quote. If the new dest cents differ from the FSM, write nothing and replace the prompt with the new confirm.
   - Otherwise debit the source by the source cents and credit the destination by the dest cents. A negative source balance stays allowed.
10. One `transfer` operation on the source bank. `amount_cents` is the positive source amount. `balance_after_cents` is the source balance after. `meta` stays the destination bank id.
11. Migration `004_transfer_fx.sql`:
    - `dest_amount_cents BIGINT NULL` — cents credited to the other bank; NULL when currencies match
    - `fx_rate TEXT NULL` — decimal string of destination units per 1 source unit, same ratio as the quote, not the rounded label; NULL when currencies match
12. Success edits the prompt into an outcome (💸, buttons removed). Name both amounts and both new balances with `FormatMoney`. A second tap is a stale callback and must not move money again.
13. Wire `internal/adapter/fx` into `cmd/bot` with the production Redis cache and `net/http`. Service takes `RateProvider`. Same-currency tests assert `Quote` is not called.

Slash shortcut `/transfer A B 10` follows the same fork: same currency writes immediately; different currency stops at the confirm.

## Out of scope

- Asking for a destination currency
- Converting `/all` or `/total`
- Recoding a bank (`/currency`)
- A rate API key. The `FX_*` durations already exist from `4.14.1`; pass those parsed values into the adapter
- `/history` rendering of `fx_rate` (`4.10` can read the columns later)

## DoD

- Same-currency transfer tests still pass and still do not call `Quote`
- Cross-currency Yes writes the converted cents and both new columns
- No, `/cancel`, rate failure, and a zero dest amount write nothing
- A quote that moved between confirm and Yes does not write the stale dest amount
- `make test-unit`, `make lint`, and `make test-integration` pass

## Tests

- Domain convert: `100` cents × `30/1` = `3000`; `1` cent × `3/2` = `2`; `1` cent × `1/1000` = `0` → `ErrConvertedAmountZero`; half-away `-3/2` → `-2`.
- Service, mockery `RateProvider`: different currency calls `Quote` once per attempt; same currency does not; provider error leaves both balances; success stores `dest_amount_cents` and `fx_rate`.
- Handler: confirm text contains both formatted amounts; No writes nothing; stale Yes does not double-post.
- Integration: a same-currency transfer row leaves both new columns NULL; a cross-currency row written by the service (mockery `RateProvider`) stores `dest_amount_cents` and `fx_rate`.
