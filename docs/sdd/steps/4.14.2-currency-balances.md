# 4.14.2 Currency balances

- **Status:** `todo`
- **Goal:** one bank holds one balance per currency. `/add`, `/spend`, and `/set` name that currency. `/currency` is removed. Same-currency `/transfer` moves one currency and can open it on the destination bank.
- **Depends on:** [`4.13.3`](4.13.3-currency-picker.md). [`4.14.1`](4.14.1-fx-rates.md) is not required.
- **Read with this file:** [`requirements.md`](../requirements.md) (Currencies and FX), [`areas/telegram.md`](../areas/telegram.md), [`areas/service.md`](../areas/service.md), [`areas/persistence.md`](../areas/persistence.md).

No exchange rate in this step. Two different currencies are [`4.14.3`](4.14.3-fx-transfer.md).

## Storage

Migration `internal/adapter/postgres/migrations/004_bank_balances.sql`. Copy first, then drop.

```sql
CREATE TABLE bank_balances (
    bank_id BIGINT NOT NULL REFERENCES banks (id) ON DELETE CASCADE,
    currency TEXT NOT NULL,
    balance_cents BIGINT NOT NULL,
    PRIMARY KEY (bank_id, currency)
);

INSERT INTO bank_balances (bank_id, currency, balance_cents)
SELECT id, currency, balance_cents FROM banks;

ALTER TABLE operations ADD COLUMN currency TEXT;

UPDATE operations AS o
SET currency = b.currency
FROM banks AS b
WHERE o.bank_id = b.id
  AND o.type IN ('add', 'spend', 'set', 'transfer');

ALTER TABLE banks DROP COLUMN balance_cents;
ALTER TABLE banks DROP COLUMN currency;
```

- A currency exists in a bank when its `bank_balances` row exists. A zero row stays.
- `include_in_total` stays on `banks`. Every balance in that bank is included or excluded together.
- `operations.currency` stays nullable. The backfill covers add, spend, set, and transfer rows whose bank still exists. Rename, delete, historical `currency` rows, and rows whose bank was deleted stay NULL. Do not rewrite those amounts.
- Keep `currency` in `operations_check`. This step writes no new `currency` operation.
- No extra index. The primary key is the lookup. Totals join `bank_id`.

## Domain and service

Replace `Bank.Balance` and `Bank.Currency` with `Balances []Balance` (`Currency` + `Money`). Sort with the existing total rank: `USD`, `EUR`, `USDT`, then other codes A→Z. One rank function for balances and for totals.

`BankRepository` grows the balance reads and writes. Do not add a second repository. Every method stays scoped by `userID`.

Lock the bank row or rows first (`FOR UPDATE`, ascending id when two banks are locked), then read and write `bank_balances` in that transaction. Insert a missing balance inside that transaction. The primary key is the guard; keep the existing deadlock and serialization retry.

`ParseCurrency` is unchanged. The service parses the code again. Handlers do not pass raw text through.

Amount rules stay as they are. Add and spend reject a negative and allow zero. Set allows any parsed amount, including negative and zero. Transfer rejects zero and a negative.

- `CreateBank` inserts the bank, one balance at `0` in the chosen code, and sets `last_currency`, in one transaction.
- `Add` creates a missing balance at the amount, or adds to the existing row.
- `Set` creates a missing balance at the amount, or replaces the row.
- `Spend` of a missing currency returns `ErrCurrencyNotInBank` and inserts nothing. Spend of an existing row may go negative.
- `Delete` removes the bank. Cascade removes its balances. One `delete` operation: `currency` NULL, `amount_cents` 0, `balance_after_cents` NULL, `meta` the bank name. Old delete rows keep the amount they already have.
- `Rename` does not move money. New rename rows: `currency` NULL, `amount_cents` 0, `balance_after_cents` NULL, `meta` `Old -> New`.
- `Transfer(ctx, userID, fromID, toID, currency, amount)` is same-currency only. `ErrSameBank` when the ids match. `ErrCurrencyNotInBank` when the source row is missing. A missing destination row is inserted, then credited by the same cents. One `transfer` operation on the source bank: `currency` set, `amount_cents` the positive amount, `balance_after_cents` the source balance after, `meta` the destination bank id.
- Remove `ErrCurrencyMismatch` and `ChangeCurrency` when nothing returns them.
- Add, spend, set, and transfer set `last_currency` to the code they applied.
- `TotalIncluded` sums `bank_balances` for included banks, grouped by currency. A bank with two currencies contributes to two groups. A currency that sums to `0` still appears. No included banks stays one `USD` total of `0`.

Success copy for add, spend, set, and transfer names the currency that changed (`FormatMoney`) and that currency’s balance after. It does not list the bank’s other balances.

## Display

`/bank`, `/banks`, and the bank list inside `/all` use one card. Catalogs `en`, `ru`, `uk`, `md`. English source:

```text
Travelling (in total):
• $240.00
• 600.00 USDT
```

```text
Gifts (not in total):
• 8.00 MDL
```

The include flag sits on the header. Bullets use `FormatMoney`, in rank order, zeros included. `/newbank` shows the new zero line (`• $0.00`). A bank with no rows is the header only. `/total` and the `/all` total block keep today’s heading and one sum per currency. No conversion.

## `/newbank`

Unchanged through the currency picker. The chosen code is the first balance at `0`. `/cancel` on that step still writes nothing and does not change `last_currency`.

## `/currency`

Remove the command from the menu, `/help`, the empty-wizard compact list, callbacks (`v1:currency:…`), and the handler. Keep `v1:ccy:` for the picker. Historical `currency` rows stay readable. Do not write new ones.

## Add, spend, set

Wizard: bank → currency → amount. The amount is still a number (`10`, `10.5`, `10.50`). `$100` and `100 USD` stay invalid amounts. The amount prompt names the unit, as today: `How much should I add to "Travelling" (PLN)?` with `$` for USD, `€` for EUR, and the code otherwise.

Currency step, English source, same meaning in every catalog:

```text
Which currency should I add to "Travelling"?
For a different one, send its code, for example UAH.
```

Spend and set use the same shape (`spend from` / `set in`). Spend has no “send its code” line.

Buttons reuse `v1:ccy:CODE`.

- Add and set: one row of currencies already on that bank (display label, rank order), then the existing picker row (`€`, `$`, `USDT`, plus `last_currency` when it is outside those three) with any code already shown removed. A typed code goes through `ParseCurrency`. Invalid text uses today’s invalid-currency copy and stays on the step.
- Spend: only the existing-currency row. One existing currency skips this step. A typed valid code the bank does not have stays on the step: `"Travelling" has no PLN.` An invalid code uses the invalid-currency copy.
- Add and set do not skip this step when the bank has one currency. That step is how the next currency appears.

Shortcut, case-insensitive bank lookup. Split the payload on whitespace:

1. The full text is an existing bank → currency step, no amount yet. This wins over splitting, including a bank whose name ends in a number.
2. The last token is a currency, the token before it is an amount, and the rest is an existing bank → use that currency. Add and set create a missing balance and write. Spend of a missing currency is an outcome, no write, no new row: `"Travelling" has no PLN.`
3. The token before the last is an amount and the last token is not a currency (`100 BTC`) → the invalid-currency outcome. No write.
4. The last token is an amount and the rest is an existing bank → one balance uses that currency; several balances keep the bank and the amount and ask for the currency. A bank named `USD` still matches here, because the amount is the last token.
5. Anything else keeps today’s unknown-bank outcome. An empty command stays the wizard.

`/add Holiday Fund 100 PLN` and `/add Travelling 100` (one balance) both write. `/add Travelling 100` with several balances asks for the currency.

## Same-currency transfer

Wizard: from-bank → source currency → to-bank → amount → write. No quote and no extra confirm.

- Source currency buttons are the balances on that bank. One balance skips the step. Spend’s missing-currency rule applies: a currency the bank does not have cannot be chosen.
- The to-bank list omits the source bank. One bank in the account keeps today’s “create another bank” reply.
- The destination currency is the source currency. Do not ask for it. Create that row on the destination when it is missing, including when the destination’s other balances use different codes.

Shortcut: today’s shape, exactly two single-word names and an amount (`/transfer A B 50`). Both banks must exist.

- The source bank has one balance → that currency. Create it on the destination when missing, and write.
- The source bank has several → keep both banks and the amount, and ask for the source currency.
- Otherwise the full remainder is the from-bank name, as today.

[`4.14.3`](4.14.3-fx-transfer.md) replaces this shortcut when each bank has one balance and those codes differ, and it adds the destination-currency step. Do not call `Quote` here.
