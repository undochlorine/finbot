## In scope

- `domain.ParseCurrency(raw) (code string, error)`:
  - Trim, then uppercase.
  - `USDT` is valid.
  - Otherwise valid only when `golang.org/x/text/currency.ParseISO` accepts it (active ISO 4217, three letters, including metal codes such as `XAU`).
  - Reject symbols (`$`, `€`), names (`dollar`), 2-letter codes, spaces, digits, and any other crypto (`BTC`).
  - Return the canonical uppercase code (`usd` → `USD`, `usdt` → `USDT`).
- `domain.FormatMoney(m Money, code string) string`. `Money` stays `int64` minor units with **2** decimal places for every code, including JPY and USDT. Decimal point is `.`.
  - `USD` → `$10.00`, negative `-$10.00`, zero `$0.00`. No space.
  - `EUR` → `€10.00`, negative `-€10.00`. No space.
  - Every other code, including `USDT` → `10.00 UAH`, `10.00 USDT`, negative `-10.00 UAH`. One space before the code.
  - Never print the letters `USD` or `EUR`. An unknown code uses the space-and-code form.
- Constants for `USD`, `EUR`, `USDT`.
- Promote `golang.org/x/text` to a direct module requirement. Do not vendor a hand-written ISO list.
- Migration `internal/adapter/postgres/migrations/002_currency_usd.sql`. The runner already applies `migrations/*.sql` in order and records `schema_migrations`. Do not add `banks.currency`; `001_init.sql` already has `TEXT NOT NULL DEFAULT 'USD'`.
  - `UPDATE banks SET currency = 'USD';` so every row that already exists is dollar, whatever it stored.
  - `ALTER TABLE users ADD COLUMN last_currency TEXT NOT NULL DEFAULT 'USD';`
- `domain.User.LastCurrency`. Scan it on user reads. Leave it **off** the `Upsert` `INSERT` column list and **off** the `ON CONFLICT DO UPDATE` set, so the SQL default fills new users and a later `/start` does not wipe it.
- `CreateBank` still writes `DEFAULT_CURRENCY` until [`4.13.3`](4.13.3-currency-picker.md). Do not ISO-check that env var here.

## Tests

Table-driven `ParseCurrency` and `FormatMoney`: the three display forms, negatives, zero, `uah` / `Usdt` canonicalization, and rejections (`$`, `€`, `BTC`, `US`, `UAH1`, empty).

Integration: `schema_migrations` contains `002_currency_usd`; omitted currency and omitted `last_currency` default to `USD`; a second `Upsert` does not change `last_currency` after a direct SQL update of that column.

Do not re-apply `002` inside the test. The `UPDATE` exists for databases that already have bank rows when the migration runs.
