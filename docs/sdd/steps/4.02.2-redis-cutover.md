# 4.2.2 Redis cutover

- **Status:** `done`
- **Goal:** `cmd/bot` uses Redis for `Cache`. `memorycache` stays for unit tests only.

**Depends on:** `4.2.1` `done`. **Design:** [`docs/superpowers/specs/2026-09-09-redis-cache-design.md`](../../superpowers/specs/2026-09-09-redis-cache-design.md)

## In scope

- `config.Load`: require `REDIS_URL` (`redis://` or `rediss://`, host non-empty)
- `cmd/bot`: `rediscache.Open`, pass the cache into `telegram.New`, `defer Close` (same shutdown shape as Postgres)
- `.env.example`, `README.md`, `docs/sdd/areas/telegram.md`, `docs/sdd/areas/platform.md`, `docs/sdd/areas/service.md`: Redis as **current** Cache; `memorycache` is tests-only
- Dockerfile / human run: `REDIS_URL` at run time (no Redis volume as a store)
- `cmd/bot` tests: missing/invalid `REDIS_URL` and unreachable Redis fail like the Postgres cases

## Out of scope

- Managed Redis, vendor, TLS-as-hosting (`4.3` — `rediss://` already parsed)
- Rate limits, replicas, FIFO-in-Redis, snapshot cache (`4.9`)
- Deleting `memorycache` or changing telegram FSM JSON / `fsmTTL`
- Changing command UX

## DoD

- Bot does not start without a usable `REDIS_URL` and a successful ping
- `go run ./cmd/bot` against Compose Postgres **and** Redis serves Telegram the same as memory Cache (commands and FSM TTL unchanged)
- Process restart **keeps** an in-flight wizard if Redis still holds the key; Redis restart expires wizards
- `make lint`, `make test-unit`, `make test-integration` pass
- Area docs describe Redis as **current**, not upcoming

## Tests

- Config: missing/invalid `REDIS_URL` fails load
- `cmd/bot`: unreachable Redis fails `run` with a `redis` error prefix (mirror `TestRunUnreachablePostgres`)
