# PostgreSQL cutover (Stage 4.1)

Replace the MVP SQLite store with PostgreSQL as the **only runtime database**. Service ports stay. Local and CI use Compose / a GitHub Actions Postgres service. Managed hosting, backups, and TLS are `4.3`. Partitioning, PgBouncer, replicas, and rate limits are `4.9`.

No real users yet. SQLite → Postgres copy is **best-effort** (nice if a local `data/finbot.db` comes across; not a lossless guarantee, not a blocker).

## Goal

`cmd/bot` talks only to Postgres. Bank/user/operation behavior matches today’s service tests. Money writes stay atomic under concurrent connections. Schema is a production baseline, not a replay of SQLite `001`–`003`.

## Non-goals

- Dual `DB_DRIVER=sqlite|postgres` after cutover
- ORM, sqlc, golang-migrate CLI
- Partitioning, logical replication, read replicas, PgBouncer
- Advisory locks, outbox, JSONB `meta`
- Redis (`4.2`), hosting vendor (`4.3`), `/history` UX (`4.10`)
- A supported product importer or checksum campaign

## Decision (locked)

**C — Postgres-only runtime.** New `internal/adapter/postgres`. Baseline schema. Same `service` repository + `Transactor` ports. Delete SQLite from the bot, Docker, and CI at `4.1.3`.

Rejected: long-lived dual driver (two dialects forever); ORM/sqlc (≈10 queries).

## Current seam

Hexagonal layout already isolates SQL:

- `internal/service` owns `BankRepository`, `UserRepository`, `OperationRepository`, `Transactor`
- `internal/adapter/sqlite` implements them (`?` placeholders, `LastInsertId`, TEXT timestamps, `MaxOpenConns = 1`)
- Unit tests mock service interfaces (mockery). Integration tests use a temp SQLite file

Do not change product commands. Do not move SQL into `service`.

What SQLite hid and Postgres must not:

| MVP | Postgres |
| --- | --- |
| One writer (`MaxOpenConns = 1`) | Pool + `SELECT … FOR UPDATE` inside `InTx` |
| SQLite `INTEGER` (64-bit) for Telegram ids | `BIGINT` (`INTEGER` in Postgres is 32-bit) |
| `LastInsertId` | `RETURNING` |
| Replay `001`–`003` (SQLite table rebuilds) | One baseline `001_init.sql` |
| Unique errors via `modernc.org/sqlite` | `23505` → `domain.ErrBankNameTaken` |

## Architecture

```text
cmd/bot
  config.Load  →  DATABASE_URL
  postgres.Open (pool, timeouts, ping, migrate)
  service.New(postgres repos, postgres Transactor, …)
  telegram.New

internal/adapter/postgres/
  open.go          sql.Open pgx stdlib, pool, SET timeouts, Ping
  migrate.go       embed migrations, schema_migrations, transactional apply
  tx.go            InTx, ctx *sql.Tx, deadlock retry
  user.go bank.go operation.go
  conv.go          timestamptz scan, 23505 map
  migrations/001_init.sql
```

Driver: `github.com/jackc/pgx/v5/stdlib` so `Transactor` can keep `*sql.DB` / `*sql.Tx` on the context (same pattern as SQLite). Placeholders `$1`. No shared SQL strings with SQLite.

Migrations stay **embed-at-startup**, numbered SQL, recorded in `schema_migrations`. Postgres files are a new series in the postgres package. Do not run SQLite scripts on Postgres.

## Schema (baseline)

Create `users`, `banks`, `operations` in one `001_init.sql`. Semantics match [`docs/sdd/areas/persistence.md`](../../sdd/areas/persistence.md); types do not.

- `users.telegram_id BIGINT PRIMARY KEY`
- `banks.id` / `operations.id` — `BIGINT GENERATED BY DEFAULT AS IDENTITY` (optional import can set ids; then `setval`)
- All timestamps `TIMESTAMPTZ NOT NULL` (UTC)
- `include_in_total BOOLEAN NOT NULL`
- `banks.currency TEXT NOT NULL DEFAULT 'USD'`
- `users.locale TEXT NOT NULL DEFAULT 'en'`
- `users.discount_percent INTEGER NULL` with `CHECK (… IS NULL OR (… BETWEEN 0 AND 100))`
- `users.referred_by BIGINT NULL`
- `name_normalized TEXT NOT NULL`, filled by `domain.NormalizeBankName` (not `lower()`)
- `UNIQUE (user_id, name_normalized)`
- FKs: `banks.user_id` and `operations.user_id` → `users(telegram_id) ON DELETE CASCADE`
- `operations.bank_id` → `banks(id) ON DELETE SET NULL`
- `operations.type` `CHECK` in `('add','spend','set','delete','transfer','rename')`
- `meta TEXT` (empty still SQL NULL). Not JSONB.

**Indexes now** (access paths, not partitioning):

- `banks (user_id)`
- unique `(user_id, name_normalized)` (constraint)
- `operations (user_id, created_at DESC)` — ready for `4.10`
- `operations (bank_id)`
- `users (last_activity_at)` — ready for `4.4`

`4.9` may range-partition `operations` on `created_at`. That is why ids are `BIGINT IDENTITY` and timestamps are `TIMESTAMPTZ`. Do not partition in `4.1`.

## Load resistance and data safety (now vs later)

**Now (4.1.1–4.1.2):**

1. **Pool** — defaults: `MaxOpenConns = 10`, `MaxIdleConns = 5`, `ConnMaxLifetime = 30m`, `ConnMaxIdleTime = 5m`. Constants in code, not a pile of env vars. Unbounded `database/sql` defaults are not acceptable.
2. **Session timeouts** on the role/connection after connect: `statement_timeout = 5s`, `lock_timeout = 2s`, `idle_in_transaction_session_timeout = 10s`. Query calls still take `context`.
3. **Row locks** — `GetByID` / `GetByName` append `FOR UPDATE` **only when** the context carries a transaction. Unlocked reads outside `InTx` (list, total, get for display).
4. **Lock order** — `Transfer` loads the two banks by **ascending id**, then applies from/to updates. Opposite transfers must not deadlock.
5. **`InTx` retry** — up to 3 attempts on Postgres `40P01` (deadlock) and `40001` (serialization). Then return the error. Do not retry other failures.
6. **Unique backstop** — concurrent `/newbank` still maps unique violation to `ErrBankNameTaken`. `CreateBank` may stay Get-then-Insert; the constraint is the race winner.
7. **Fail closed** — migrate or ping failure → process exits, does not long-poll Telegram.
8. **Isolation** — every per-user query includes `user_id` (already true). Keep leak tests.

**Not now (`4.3`):** managed instance, disk size, TLS in the URL (`sslmode=require`), secrets, automated backups / PITR, restore drill. Compose volume is local-only.

**Not now (`4.9`):** `operations` partitioning, PgBouncer, app replicas, per-user rate limit / token bucket, extra advisory locks. Pooling and `FOR UPDATE` are already done; do not rebuild them.

## Config

After `4.1.3`, `DATABASE_URL` is required (Postgres URL). `SQLITE_PATH` is removed from `cmd/bot`.

Until `4.1.3`, `cmd/bot` still uses `SQLITE_PATH`. `4.1.1` may parse `DATABASE_URL` for tests/Open without switching the bot.

Local default (Compose):  
`postgres://finbot:finbot@127.0.0.1:5432/finbot?sslmode=disable`

Tests:  
`POSTGRES_TEST_URL` or default  
`postgres://finbot:finbot@127.0.0.1:5432/finbot_test?sslmode=disable`

Compose creates both databases. Credentials `finbot`/`finbot` are **local/CI only**.

## Compose and CI

**Local:** `docker-compose.yml` (or `compose.yaml`) with `postgres:16`, healthcheck `pg_isready`, named volume, init script creating `finbot_test`. Not required in CI.

**CI:** GitHub Actions **service container** `postgres:16`, same user/password, `POSTGRES_DB=finbot_test`, job waits on health, `make test-integration` uses `POSTGRES_TEST_URL`.

`make test-integration` after `4.1.1` includes `./internal/adapter/postgres/...`. After `4.1.3` it no longer runs `./internal/adapter/sqlite/...`.

## SQLite import

No production dataset. **Greenfield Postgres is the expected path.**

`4.1.3` may include a short, best-effort copy (domain rows, `GENERATED BY DEFAULT` so ids can be preserved when that is the simple insert path, then `setval`). Missing file, empty DB, or a failed row: log and continue. No dual-write, no checksum gate, no rollback product.

After the bot is on Postgres, **delete** `internal/adapter/sqlite` from the runtime and CI. Do not keep a second dialect “just in case.” If an import helper was used in the same step, it can go away with the sqlite package; leftover personal SQLite data is acceptable to drop.

## Testing

- Unit tests: unchanged (mockery on service interfaces).
- `4.1.1`: migrate twice (idempotent), ping, schema/index existence. Tests **fail** if Postgres is unreachable (tell the operator to start Compose); they do not skip.
- `4.1.2`: same behavioral cases as today’s sqlite integration (CRUD, per-user isolation, unique name, write-path add/spend/set/delete/rename/transfer atomicity). Prefer a small shared `storetest` harness behind the service ports, or postgres-package tests that construct `service.New` with postgres repos. Do not hand-write fakes for those ports.
- `4.1.3`: `cmd/bot` fails without `DATABASE_URL`; Docker/README/env examples use Postgres.
